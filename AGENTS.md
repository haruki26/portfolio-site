# AGENTS.md

This file is read by OpenCode before any tool call. Keep guidance short, repo-specific, and verifiable.

## Role

You are an expert full-stack engineer working on a personal portfolio site. The repo is a pnpm workspace with a Cloudflare-deployed TanStack Start app and some shared library packages. Read the package-specific `AGENTS.md` (one per workspace package) before editing inside a package.

## Commands (run from repo root)

Install / setup:

- `mise trust && mise i` — install pinned Node 24, pnpm 11.1, Rust 1.94 (defined in root `mise.toml`).
- `pnpm i` — install workspace deps. `pnpm-workspace.yaml` sets `minimumReleaseAge: 1440` (minutes), so brand-new releases are blocked.
- `mise run -C packages/motion-core setup` — one-time install of `wasm-bindgen-cli` (only needed if you touch Rust).
- `docker compose up` — full dev container (uses `Dockerfile` + `docker-compose.yaml`, watches via polling).

Workspace-wide:

- `pnpm build` — runs `vite build` for every workspace package.
- `pnpm -r lint|format|check` — Biome across all packages (root config is the single source).
- `pnpm -r test` — Vitest in every package (each has its own `vitest.config.ts`).

Per-package (use the version that matches what you are editing):

- `pnpm dev` (alias of `pnpm -C app dev`) — Vite dev server at `:3000`.
- `pnpm -C app test|lint|format|check|deploy|storybook` — see `app/AGENTS.md`.
- `pnpm --filter @repo/cms build|test|check|lint|format` — see `packages/cms/AGENTS.md`.
- `pnpm -C packages/motion-core <task>` for TS scripts; `mise run -C packages/motion-core wasm:build` for the Rust→WASM build — see `packages/motion-core/AGENTS.md`.

CI parity (what GitHub Actions runs):

- `pnpm -C app ci:check` (= `biome check`) → `pnpm -C app ci:type` (= `tsc --noEmit`) → `pnpm -C app test:coverage`.
- Same triplet under `packages/cms/` (driven by `ts-ci.yaml` with `working_directory`).

## Repo layout (one-liner per area)

- `app/` — deployable TanStack Start site (Cloudflare Workers). See `app/AGENTS.md`.
- `packages/cms/` — `@repo/cms` microCMS client. See `packages/cms/AGENTS.md`.
- `packages/motion-core/` — Rust→WASM motion math, used as `@pkg/motion_core`. See `packages/motion-core/AGENTS.md`.
- `.github/workflows/` — `check-site.yaml`, `check-cms.yaml` both call the reusable `ts-ci.yaml`; `deploy.yaml` runs `pnpm -C app deploy` after `Run Site Check` succeeds on `main`.
- `biome.json` (root) — single lint/format config. Per-package `biome.json` only overrides `files.includes`.
- `tsconfig.base.json` — strict TS (`noUnusedLocals`, `noUnusedParameters`, `verbatimModuleSyntax`, `composite`, `noEmit`).

## Hooks / CI

- `lefthook` runs at the root and extends `packages/*/lefthook.yaml` + `app/lefthook.yaml`.
  - pre-commit: `biome check --write` on staged files, scoped per package.
  - pre-push: `ci:type` and `test` per package, run in parallel.
- `ts-ci.yaml` skips the test job for PR drafts and `release*`/`doc*` branches.
- Renovate (`enabledManagers: ["npm", "mise"]`, `rangeStrategy: pin`) auto-merges patch/minor updates; assignees: `haruki26`.
- Deploy: `deploy.yaml` writes `.env` from GitHub secrets (`MICROCMS_API_KEY`, `MICROCMS_SERVICE_DOMAIN`, `FORM_API_URL`) and needs `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID`.

## Cross-package boundaries

### Always do

- Run `mise i` before `pnpm i`.
- Respect per-package boundaries in commits.
  - CMS changes still ship through `app/` deploy, but commit them on `feature/cms-*` branches per repo convention.
- Follow the `Result` pattern when adding new server fns (see `app/AGENTS.md`).

### Ask first

- Change pinned tool versions in `mise.toml` or workspace catalog.
- Edit `.github/workflows/*`.
- Touch `wrangler.jsonc` or `compatibility_flags`.

### Never do

- Commit secrets (`.env`, `app/.env`, anything in `*.local`).
- Hand-edit `app/src/routeTree.gen.ts` or `packages/motion-core/pkg/`.
- Import the microCMS client directly into a server function — always go through `getCMSClientMiddleware`.
- Add a `.lazy.tsx` sibling to a route file. The lazy-route pattern is being removed — write to `index.tsx` instead.

## Cross-package conventions

- All `*.test.{ts,tsx}` files live next to source. `tsconfig.json` includes them, so types must compile.
- JS style: single quotes, semicolons as-needed, trailing commas everywhere (root `biome.json`).
- PR template at `.github/pull_request_template.md` is in Japanese — match the existing `## 概要` / `## 変更点` headings.
