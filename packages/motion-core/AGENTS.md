# packages/motion-core/AGENTS.md

Read this when editing inside `packages/motion-core/`. The repo root `AGENTS.md` covers workspace-wide commands.

## Role

You are working on `motion-core`, a Rust crate compiled to WebAssembly via `wasm-bindgen` and re-exported to TypeScript. It is the workspace's motion-math kernel (currently a stub `add`). Consumers import from `@pkg/motion_core` (the wasm-bindgen output) and go through the TS facade at `ts/index.ts`.

## Stack

- **Rust:** 1.94 (pinned in `packages/motion-core/rust-toolchain.toml`, with `rustfmt` + `clippy` + `wasm32-unknown-unknown` target)
- **Rust deps:** `wasm-bindgen = 0.2.114`, `tsify-next = 0.5.4`, `serde = 1.0.215`, `thiserror = 2.0.18` (`Cargo.toml`)
- **TS bridge:** `ts/index.ts` re-exports a lazy `createWasm()` that calls `init()` from `@pkg/motion_core` exactly once
- **Bundler:** Vite 7 (workspace catalog) with `vite-plugin-wasm` + `vite-plugin-top-level-await`
- **Lint/format:** Biome 2.2 over `ts/**/*` only (the wasm-bindgen output in `pkg/` is excluded by `packages/motion-core/biome.json`); `rustfmt` + `cargo clippy` over `src/**/*.rs` (pre-commit hook)

## Commands

Setup (one time):

- `mise run -C packages/motion-core setup` — installs `wasm-bindgen-cli`. Required before any wasm build.

Build:

- `mise run -C packages/motion-core wasm:build` — runs `cargo build --target wasm32-unknown-unknown --release` then `wasm-bindgen target/wasm32-unknown-unknown/release/motion_core.wasm --out-dir ./pkg --target web`. Output goes to `pkg/`.
- `pnpm -C packages/motion-core build` — `vite build` of the TS facade to `dist/index.mjs` (consumer entry).
- `pnpm -C packages/motion-core check` — `wasm:fmt` (cargo fmt) + `ts:check` (biome check --write). Lints Rust and TS together.
- `pnpm -C packages/motion-core lint` — `wasm:lint` (cargo clippy) + `ts:lint` (biome lint).
- `pnpm -C packages/motion-core format` — `wasm:fmt` + `ts:fmt`.

Plain Rust (works without `mise`):

- `cargo fmt` / `cargo clippy` / `cargo build --target wasm32-unknown-unknown --release` from this directory.

## How the TS↔Rust bridge works

1. Rust code in `src/lib.rs` and `src/core/*` exposes `#[wasm_bindgen]` functions.
2. `wasm:build` produces `pkg/motion_core.{js,d.ts,_bg.wasm}` via `wasm-bindgen --target web`.
3. The TS facade at `ts/index.ts` imports the JS glue as `@pkg/motion_core` (alias defined in `vite.config.ts`: `@pkg` → `pkg/`).
4. Consumers call `createWasm()` to lazily `init()` the module — the instance is memoised so subsequent calls return the same `InitOutput`.

Good (TS facade):

```ts
import init, { type InitOutput } from '@pkg/motion_core'

let wasm: InitOutput | null = null

export const createWasm = async () => {
  if (!wasm) wasm = await init()
  return wasm
}
```

Good (Rust export):

```rust
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

Bad: importing from `pkg/motion_core_bg.wasm` directly (consumers must go through `@pkg/motion_core` so the JS glue loads first), or calling `init()` in module top-level (must be inside `createWasm` so it can be lazy and testable).

## Boundaries

### Always do

- Run `mise run -C packages/motion-core wasm:build` after editing Rust.
- Re-run `pnpm -C packages/motion-core build` so `dist/index.mjs` reflects the new facade.
- Keep `wasm-bindgen` exports in `src/lib.rs` thin and delegate to `src/core/`.
- Run `cargo fmt` and `cargo clippy` before committing.

### Ask first

- Change `Cargo.toml` deps.
- Change `rust-toolchain.toml`.
- Change the `wasm-bindgen --target` flag.
- Change `crate-type` in `[lib]`.

### Never do

- Hand-edit anything under `pkg/`. Rebuild instead.
- Commit `target/`, `pkg/`, or `dist/`.
- Change the alias in `vite.config.ts` (`@pkg` → `pkg/`, `@` → `ts/`) without also updating every consumer.
- Add `.lazy.tsx`-style indirection in `ts/index.ts`. Keep it a single function.
